# Rust v0.3.4：后台崩溃修复验证

日期：2026-10-01。修复开始检测后程序访问异常退出、网页显示 Failed to fetch 的问题。

## 根因与修复

v0.3.3 的环境检查线程先初始化 Windows Runtime 并创建 OCR 引擎，随后退出；整个程序没有长期保持初始化的线程。后续检测线程使用进程缓存的 Language 工厂时访问了失效的 COM 对象。Windows 报 0xc0000005，后台 HTTP 进程随之消失。

隔离测试用真实可见的临时窗口、实际 exe、真实系统 OCR 和 `/api/start` 复现。定点日志显示：环境线程完成 OCR 创建，检测线程找到窗口，进入 Language 工厂创建后崩溃，尚未创建 trace 文件或进行截图。原二进制故障偏移处为间接调用工厂虚表。排查日志仅用于定位，发布源码已移除。

修复由 `native/src/runtime.rs` 的线程绑定 Apartment 守卫管理：

- 主线程在启动时初始化 WinRT MTA，并保持到程序退出，覆盖所有环境检查、重试和检测工作线程，防止线程间隙导致运行时与缓存工厂失效。
- 每个 OCR Engine 成对初始化与释放 WinRT；字段顺序保证先释放 OCR 对象，再调用 RoUninitialize。
- 守卫通过线程绑定类型约束禁止跨线程移动或共享。
- 前端请求断连显示中文恢复说明，后续请求成功后清除连接错误提示。

官方生命周期说明：[RoInitialize](https://learn.microsoft.com/windows/win32/api/roapi/nf-roapi-roinitialize)、[缓存工厂指向已释放内存的案例](https://devblogs.microsoft.com/oldnewthing/20211105-00/?p=105878)。具体故障结论来自本项目的原版复现和修复后同路径对比。

## 实际验证

1. **先红后绿**：`python tests/native_live_qa.py <原 v0.3.3 exe>` 失败，进程退出码为 `0xc0000005`；相同测试指向 v0.3.4 通过。
2. 修复后的初始复现驱动持续约 25 秒，实际完成 216 轮观察，后台状态仍可读取。
3. 新增正式回归 `tests/native_live_qa.py`：连续三轮真实截图/OCR、并发请求状态/历史/十箱统计、正常停止、重新检测 OCR 环境，再次开始。每轮要求至少三次实际图像观察，不能仅以进程存活或窗口遮挡算通过。
4. 14 项 Rust 单元测试全部通过；八张既有真实截图的 OCR 与红品回归全部通过。
5. 反馈 ZIP、十箱统计、路径边界、旧记录导入、人工复核重启保留与无历史反馈导出通过。
6. 干净分享 ZIP 解压后的实际 exe 再次通过真实检测三轮启停与反馈/成绩端到端测试。分享包只含 exe、规则 JSON、说明，不含用户历史、调试数据或工具链。

测试窗口和数据均在隔离目录创建，结束后关闭。测试驱动需要开发电脑的 Python/Tk，发行程序仍无需 Python。用户原版历史保留，桌面新版本合并复制两处 v0.3.3 测试目录的历史；源码与分享包不含这些记录。

## 范围

修复运行时生命周期，不更改红品检测阈值、统计口径或人工复核语义。没有重新完整播放此前四段视频，也没有在第二台 PC 测试。旧 v0.3.3 的单帧诊断与接口验证未覆盖准备线程退出后进入真实检测的路径，本次新增回归覆盖该缺口。
