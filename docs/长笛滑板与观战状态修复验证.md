# 长笛、滑板与观战状态修复验证

2026-10-05。当前 main 开发源码，未打包、未发布、未替换正式 v0.3.5 程序；Python 和历史版本快照保持原样。私人反馈截图、底部观战截图与原始日志仅在本机回放，没有上传公开仓库。历史记录不自动改判。

更新：以上修复后续已按用户要求正式打包为 v0.3.6，发布验证见 [v0.3.6验证](v0.3.6验证.md)。前述“未发布”描述对应修补验证时点。

## 原因

用户称翠玉长笛，截图中的物品名为翠玉横笛。未选中红底典型 RGB 为 (55,26,22)，亮度约 55，低于旧 V≥60；选中红底约 (74,57,56)，饱和度约 60，低于旧 S≥65。选中候选约 220×83，实测网格 85 像素，旧一格高度门限还会以 size 拒绝；完整三格长条约 255×84，宽高比约 3.04，超过旧 2.8 上限。因此不是缺少物品名称白名单。对应历史观察还曾因窗口遮挡中断，仍保留未完成，不擅自转成已结算出红。

未来滑板绿色槽位底色并非红色；拖动时两个图标渲染上的红色花纹被闭运算合并，旧候选约 185×286、填充率约 0.51，足以通过面积、尺寸和多帧门限。OCR 当时读取附近物品，未读到滑板名字，单加名称排除词不能覆盖此次误报。候选边缘偏离网格，新的对齐验证可以拒绝。

## 行为

- 颜色规则补回暗红和选中粉红；一格边框有 10% 尺寸容差，面积仍要求至少两格；允许三格、四格长条。
- 缓存实测网格起点和边长，四边至少三边对齐，容忍一边被提示遮挡。没有可靠横线时要求左右边缘对齐。保持标题屏蔽、棕底色相限制、两轮同区域确认和现有 JSON 排除词。
- 底部中央单独 OCR，命中观战或结算立即暂停，不创建保险箱会话；已有自己的观察仅保存未完成，不增加完整箱数，也不改变出红率或连续无红统计。两次连续无提示后恢复；底部遮挡不会被当作恢复。
- 底部状态约每半秒检查，事件提交前检查缓存；暂停时跳过物品检测。网页用金色暂停状态显示原因，状态 OCR 耗时与关键词写入 API/日志摘要。

自建窗口的状态 OCR 平均约 7 ms，仅为该测试环境结果，不代表所有真实电脑和游戏画面。OCR 模糊、底部提示移位、未知稀有度颜色和新物品仍需反馈回归；不宣称全物品零误报/零漏报。

开发命令：cargo test --manifest-path native/Cargo.toml；cargo build --release --locked --manifest-path native/Cargo.toml；python tests/native_observer_qa.py；python tests/native_live_qa.py。私有回归需要 AB_RED_PRIVATE_FIXTURES 指向本地截图目录；测试线程使用与主程序同寿命的 MTA，避免不同测试间缓存 WinRT 工厂失效。
