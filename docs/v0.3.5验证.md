# Rust v0.3.5 误报修复验证

日期：2026-10-02。基线 v0.3.4；只更新 Rust。读取桌面新建文件夹的两份反馈 ZIP，以及 v0.3.4 分享版的本地日志与对应截图。

## 原因与复现

- 柯恩币：反馈截图中的64×64 红色拖动位置提示。旧算法以标题字高 15×3=45 推算格子，两格面积门限 4050 小于候选面积 4096。颜色、填充率和两帧票数均通过，物品 OCR 为空也不否决，最终误报。
- 笔记本电脑：反馈截图中的棕底物品。棕底常见 RGB 为 (74,60,53)、(76,60,54)，符合旧 H≤9、S≥65、V≥60 分支；闭运算填补图案空隙后候选 136×169、extent≈0.398，多帧投票确认。OCR 已识别笔记本，但旧词表没有该词；名字本来就不是红品白名单，因此没有否决。
- 网页状态：本地日志中三次开箱文本均为“·等待保险箱出现”。旧条件只有包含保险箱且不超过八字，直接建立会话，没有标题语义或实际网格约束。GDI 抓屏可包含盖在工作区上的网页内容，窗口可见性采样不等于逐像素排除遮挡。
- 另外发现部分短会话来自“未搜索”斜线占位面板；该画面没有实际槽位网格。新网格门限同样拒绝这类尚未展示物品格的开箱触发。

修复前执行 cargo test --offline --locked --manifest-path native/Cargo.toml feedback_false_positives：失败列表同时包含 notebook、coin、web 状态三个真实负例。--panel 基线分别复现笔记本和柯恩币误报，陀螺仪正例通过。

## 修复

标题需以保险箱关键词结尾、长度不超过八字，排除等待、出现、打开、检测、记录、次数、搜索、寻找等状态文字。其下方还需至少三条等距长竖线；线条对比度和位置须符合槽位网格。网格线允许真实压缩截图中的浅灰亮线与暖色偏移，避免漏掉茶壶画面。

从网格测量真实边长并按锚点缓存。反馈柯恩币测得约 64 格边长，笔记本约 85；候选外接框仍须至少两格面积，因此单格提示不能确认。直接 --panel 诊断缺少网格时回退到字高四倍，正常开箱则必须有实测网格。

普通颜色分支 V<100 时收紧为 H≤6 或 H≥174，避免深棕背景 H=8–9；明亮暖红和高亮分支保留。原标题掩膜、实验室/行星 JSON 屏蔽、分区 OCR 与多帧确认保留。

## 已通过检查

- 16 项公开 Rust 单元/集成测试通过；另单独启用并通过一项私有反馈回归。反馈笔记本、柯恩币、陀螺仪分别在 0.75、1.0、1.5 倍图片下走完整 OCR→网格→跟踪→多帧链路；误报拒绝，真实大红确认。
- 网页“等待保险箱出现”与游戏“未搜索”占位画面不建立会话；常见保险箱名称与实测格子尺寸验证通过。
- 已有 8 张真实完整游戏截图回归通过，包括选中高亮、暗红、图案占满、OCR 原尺寸漏读、无面板、古董茶壶、红底断裂。
- 太阳能标题误报不确认；花瓶和短暂月球大红仍确认。
- SQLite、重启后人工复核、最佳十箱、未完成/跨运行边界、ZIP CRC/截图/空历史诊断导出检查通过。
- 实际测试窗口截图与 Windows OCR 连续三次启停、环境重试、并发状态/历史/统计请求通过。

## 范围

网格检测仅在空闲 OCR 命中候选标题时执行，红品扫描复用实测边长，不增加每帧 OCR。没有宣称所有物品和颜色均已覆盖，未重新完整播放全部视频，未在第二台 PC 验收。网格严重遮挡、截断、比例或色彩异常仍可能漏检；单格红稀有度物品仍受原两格规则限制，需要真实样本再调整。

旧历史与复核保留，不自动把原始误报改成正确统计。原始反馈 ZIP、截图、逐帧日志和个人数据库均留在本地。公开新增回归为内存生成的合成网格/颜色，不含反馈截图。私有反馈测试默认 ignored；在本地设置 AB_RED_PRIVATE_FIXTURES 为反馈样本目录，再运行 cargo test --manifest-path native/Cargo.toml feedback_false_positives -- --ignored。
