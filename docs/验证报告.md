# 红品检测验证报告

验证日期：2026-10-01。本报告区分人工期望、静态回归和正常倍速屏幕检测，不把检测器输出当作人工真值。

## 日志与问题定位

读取正在测试的旧发布版 `app/runs/20260930_214838`：36,937 条采样、31,616 次容器 OCR、20 次开箱，自动结算 18 次无红、2 次有红。记录跨度约 5 小时 38 分。旧版没有完整运行起止元数据，不能用首末事件冒充准确运行时间。

用户指出的 0024 误报是“电子保险箱”红底标签与普通太阳能充电器，经闭运算连接成 179×141 的块。修复为在形态学处理前后都排除标签，避免先合并再排除失效。物品 OCR 的裁剪原先混用了面板与工作区坐标，已统一为面板局部坐标。

另外修复：标签模板已经消失时仍扫红；不同位置的红块相互凑确认票；停止或窗口遮挡被结算为无红；选定窗口不存在时退回捕获其他窗口；保存事件失败后仍继续累加计数。这些情况现在暂停、记录未完成或明确报错。

## 检测与性能调整

红品确认需要最近 5 帧中至少 2 帧在同一位置重叠，名称排除在确认之前执行。新增亮色低饱和高亮红底分支，深红底阈值保持原有设置。月壤样本的短暂选中画面被加入回归样本。

保险箱会话内等待间隔从 0.1 秒缩短至 0.01 秒；实际频率取决于截图和检测耗时。物品 OCR 延后到几何位置得到两帧支持之后，避免第一次候选的 OCR 阻塞第二帧。普通画面继续低频全区 OCR；缓存上次标签位置的小区识别，每秒全区兜底；物品 OCR 缓存容量 64。

固定截图基准，旧源 IDLE 平均约 339 ms，新源约 10–16 ms；SESSION 约 8–12 ms。包含定期全区 OCR 的 4 秒节奏基准，处理耗时占墙钟时间约从 64% 降至 29–37%。这不是操作系统 CPU 使用率，不包含截图；提高会话采样频率会增加搜索面板出现时的采集负载。实际运行保存 capture/detect/cycle 和 OCR 耗时，可继续据此定位慢机器。完整播放采样的中位数与 P95 保存于 `tests/playback/performance.json`；这些数值没有把 OCR、截图或空闲等待当作 CPU 使用率。

## 发行与使用

v0.2.0 内置 Python 运行时，双击启动批处理即可。v0.3.0 为 Windows x64 Rust 原生 exe，网页、SQLite、PNG 编码及静态 CRT 内置，文件 3,360,768 字节（约 3.2 MiB）；依赖检查只列出 Windows 系统 DLL，无 Python/OpenCV/Rust/VC++ 运行库依赖。目标 Windows 需要中文 OCR 语言功能。分享压缩包约 1.6 MiB，仅包含 exe 和使用说明，个人 `runs` 与 `settings.json` 不在其中。两个桌面导出均已独立启动验证旧历史、误报复核标签和截图读取。

新增历史页显示开始结束时间、持续时长、完整结算数、出红率、未完成数、截图、复核标签及耗时数据。出红率按自动判定的完整结算记录计算；复核独立保存，标记误报/漏报，不覆盖原结果。未完成不进入分母。

Python 启动服务仅复用同版本、同数据目录的实例，并在 Windows 使用独占端口；旧版本占端口时会另选端口，避免新版打开旧服务。

历史页面已在浏览器中检查起止时间、时长、统计、复核交互与空目标错误提示，未发现控制台错误。验收截图见 `tests/history-native-overview.png`。

测试视频数量有限；更换分辨率、UI 缩放、遮挡或极短露出仍可能影响召回。窗口被遮挡时检测会暂停。后续增加真实游戏标注样本比继续盲调全局颜色阈值更能检验泛化效果。
